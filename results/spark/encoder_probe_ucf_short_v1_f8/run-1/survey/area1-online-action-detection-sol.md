## 對單場景警報的解讀

- **最強分數不等於最適合的 head。** TOAD 的 THUMOS’14 分數最高，但其 CLIP 與文字對齊設定不同。CMeRT 和 MOAD 較適合比較「如何使用過往 features」。
- **歷史本身不會消除場景偏差。** MiniROAD 的 recurrent state 易於建立低成本基線；GateHUB 的背景抑制與 MOAD 的 scene／action 分離，更直接針對「同場景內事件高於背景」這個問題。這是適配假設，**不是**論文已驗證的 UCF-Crime 效果。
- **起點評測比全片 frame AUC 更接近警報。** StartNet 的 p-mAP 在指定容許時間內配對正確類別的預測起點。容許偏差不是偵測延遲。對目前資料，另報每個事件的首次警報延遲、每 camera-hour 誤報數，以及未警報事件比例；逐 window 標籤只能提供約略起點。
- **已發表的 anomaly 數字不可直接比較。** 查到 REWARD 在 UCF-Crime／XD-Violence 的結果；未查到上表 OAD 方法在這兩個資料集採相同設定的已發表數字。上表也未找到以**同一影片內 AUC**報告的 OAD 結果。各論文的端到端 feature-extraction latency 多數 **not verified**；例如 [CMeRT 表 9](https://arxiv.org/html/2503.18359) 的 **126.6 FPS** 是不含 feature extraction 的模型速度，而其 [表 11](https://arxiv.org/html/2503.18359) 的等待設定允許讀取未來影像，不能用作零等待因果結果。

## 建議先試的三種方法

1. **MiniROAD 式 GRU head。** 直接讀取已存 window features，建立可重訓、低成本的因果基線。用 HOLMES-VAU window 標籤訓練，並與無歷史的 head 比較同片 AUC。
2. **GateHUB 式背景 gating。** 在因果歷史表示上學習抑制持續的背景訊號，而非直接減去不穩定的歷史平均值。先實作小型 gating ablation；其效果在 UCF-Crime **not verified**。
3. **StartNet 式起點 head。** 從 window 標籤產生起點目標，訓練與測試首次警報，而不只測試事件期間的高分。保留前兩種 head 作對照，並分開報告定位準確度與警報延遲。
